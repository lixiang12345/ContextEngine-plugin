ContextEngine Documentation

Portable, Augment-class codebase context for AI coding agents. This manual covers the full path from install to production deployment, matching contextengine-plugin v0.5.0.

What it is

ContextEngine is a small, self-contained retrieval layer: it fuses PostgreSQL full-text search, a symbol table, path matching, pgvector semantic vectors, the import/symbol graph, and commit history into one retrieval pass, then packs line-anchored context under a token budget for coding agents.

query ──► query understanding ──► FTS / symbol / path / vector recall (parallel)
                          │
                          ▼
              RRF fusion ──► feature rerank ──► (optional) neural rerank
                          │
                          ▼
              graph expansion ──► MMR diversity packing ──► agent / MCP

Four form factors

  • MCP server (stdio) — plugs into Claude Code, Cursor, or any MCP client;
  • CLI — index / search / context / status and more, for scripts and CI;
  • HTTP service — Bearer-authenticated workspace sync, background index jobs, Remote MCP, and an ops dashboard;
  • TypeScript library — embed retrieval in your own agent loop.

It works without embeddings. With no API key configured, the engine runs fully offline in BM25-only mode; configure any OpenAI-compatible embeddings endpoint to upgrade to hybrid semantic search automatically.

Install

Requirements

  • Node.js ≥ 22.5
  • PostgreSQL with the pgvector extension (a local Docker Compose is bundled; pgvector is enabled automatically by the engine)

From source (recommended)

git clone https://github.com/lixiang12345/ContextEngine-plugin.git
cd ContextEngine-plugin
npm install
npm run build
npm link   # optional: expose contextengine / contextengine-mcp / contextengine-http globally

After npm link, three executables are available anywhere: contextengine (CLI), contextengine-mcp (MCP stdio), and contextengine-http (HTTP service).

As a library

npm install contextengine-plugin
import { ContextEngine } from "contextengine-plugin";

const engine = ContextEngine.open({ root: process.cwd() });
await engine.index();
const hits = await engine.search({ query: "auth middleware" });

Try without installing

npx contextengine-plugin index
npx contextengine-plugin search "stripe payment webhook"

Quick start

Step 1: Prepare PostgreSQL

From the repository, start the bundled local pgvector service once and export the connection URL:

npm run db:up
export CONTEXTENGINE_DATABASE_URL=postgresql://contextengine:contextengine@127.0.0.1:54329/contextengine

Indexes are stored in PostgreSQL, namespaced by the workspace's absolute root path — one database can safely hold many repositories without loading their vectors into process memory. CONTEXTENGINE_DATA_DIR exists only to locate legacy SQLite indexes for one-time migration.

Step 2: Index

contextengine index              # index the current directory
contextengine index /path/to/repo   # or a specific repo

Step 3: Search and pack

# Hybrid search (auto mode by default)
contextengine search "how is rate limiting implemented"
contextengine search "processPayment" --mode bm25 -k 5

# Pack context for a development task (for your agent)
contextengine context "Add retry logic to the payment webhook"

# Index status
contextengine status

Results always carry path + line ranges, and packed context carries a retrieval trace (intent, contributing channels, token usage, index generation) — an "agent-native, not chat-native" design: every piece of evidence is locatable and verifiable.

CLI reference

All commands at a glance:

contextengine index [root] [--quiet] [--exclude <glob...>]
contextengine search <query> [-k N] [--mode auto|bm25|semantic|hybrid] [--path-prefix p] [--json]
contextengine context <task> [--max-tokens N] [--json]
contextengine status
contextengine clear-index
contextengine migrate-sqlite <legacy-index.db>
contextengine watch [root] [--debounce 800]      # live incremental re-index
contextengine serve [--auto-index]               # MCP stdio server
contextengine http [--host 127.0.0.1] [--port 8787]   # authenticated HTTP service
contextengine ci-template <github|gitlab|bitbucket>   # print an installable CI workflow
contextengine snapshot export|import|list|delete|prune|gc [name] [--store path|s3://bucket/prefix]
contextengine eval [--self | --cases file.json] [--reindex]
contextengine profile list|add|use …

index — build / incrementally update the index

Chunks the workspace at declaration/method level and writes to PostgreSQL. With embeddings configured, new and changed chunks are embedded as well. Re-runs are incremental by file hash — only changed files are processed. --exclude appends exclusion globs (equivalent to CONTEXTENGINE_EXCLUDE).

search — hybrid search

  • --mode auto (default): hybrid when embeddings are available, BM25 otherwise; or force bm25 / semantic / hybrid;
  • -k N: result count; --path-prefix: restrict by path prefix; --json: structured output.

context — pack context for a task

Takes a one-line task description and returns an MMR-deduplicated, relevance-ranked set of evidence chunks. The engine is model-neutral: it returns the complete evidence selected by topK without inspecting model names or context-window sizes; pass --max-tokens only when you explicitly need a smaller packed payload.

watch — live incremental indexing

Watches for file changes and re-indexes incrementally after a debounce (800ms by default). Ideal for long-lived local dev sessions.

Other commands

  • status — index statistics: files, chunks, embedding coverage;
  • clear-index — wipe the current workspace's index data;
  • migrate-sqlite — one-time migration of a 0.3.x-era local SQLite index;
  • serve — start the MCP server on stdio (see MCP integration);
  • http — start the authenticated HTTP service (see HTTP service);
  • ci-template — print an index-refresh workflow for GitHub Actions / GitLab CI / Bitbucket Pipelines;
  • snapshot — team index snapshots (see Index snapshots);
  • eval / profile — see Evaluation and Multi-repo profiles.

Semantic search

Without an API key, ContextEngine runs in BM25-only mode (still useful). Configure any OpenAI-compatible embeddings endpoint to enable hybrid semantic search:

export OPENAI_API_KEY=sk-...
# optional overrides:
export OPENAI_BASE_URL=https://api.openai.com/v1
export OPENAI_EMBEDDING_MODEL=text-embedding-3-small

contextengine index    # embeds new/changed chunks
contextengine search "checkout timeout" --mode hybrid

The same settings are also accepted under ContextEngine-prefixed aliases: CONTEXTENGINE_EMBEDDING_API_KEY, CONTEXTENGINE_EMBEDDING_BASE_URL, CONTEXTENGINE_EMBEDDING_MODEL.

Works with OpenAI, many proxies, and local servers that expose /v1/embeddings (e.g. Ollama-compatible gateways). The base URL may be the origin (https://gateway.example.com) or the versioned base (…/v1); ContextEngine normalizes both forms.

contextengine index

Degradation and protection

  • Each query's semantic / rerank stages get a 2000ms budget (CONTEXTENGINE_SEARCH_SEMANTIC_TIMEOUT_MS / _RERANK_TIMEOUT_MS); on timeout the engine falls back to lexical channels — retrieval never fails because a model server hangs;
  • After 3 consecutive endpoint failures the circuit breaker opens with a 30s cooldown (CONTEXTENGINE_SEARCH_BREAKER_FAILURE_THRESHOLD / _COOLDOWN_MS);
  • Every degradation shows up in the response's retrieval trace instead of happening silently.

Ignore rules

Indexing filters files in the following order, aligned with Augment Context Connectors:

  1. Built-in smart filters — node_modules/, vendor/, dist/, build/, target/, binaries, lock files, .env secrets, IDE junk, …;
  2. .gitignore (root + nested directory rules);
  3. .augmentignore (same semantics as Augment; supports ! re-include);
  4. .contextengineignore (product-specific);
  5. CLI / env — contextengine index --exclude 'vendor/**' '**/*.generated.*' or CONTEXTENGINE_EXCLUDE=….

Example .augmentignore:

# re-include something that is gitignored
!some-tracked-deps/

# exclude fixtures / local data
data/test.json
*.tmp

Multi-repo profiles

Switch the default workspace between repositories quickly:

contextengine profile add app --root ~/work/my-app
contextengine profile add api --root ~/work/my-api
contextengine profile use app
contextengine profile list

Configuration is written to contextengine.profiles.json (see examples/contextengine.profiles.example.json). You can also merge a docs repo or extra directories into the same index with CONTEXTENGINE_EXTRA_ROOTS=docs:/path/to/docs, so a single query covers code and documentation together.

MCP integration

ContextEngine speaks the Model Context Protocol over stdio; any MCP client can connect.

Claude Code

# Option 1: point at the build output
claude mcp add contextengine -- node /absolute/path/to/ContextEngine-plugin/dist/mcp-server.js

# Option 2: after npm link
claude mcp add contextengine -- contextengine-mcp

Cursor / other MCP clients

Add an MCP server entry, and set cwd to the workspace you want indexed (or set CONTEXTENGINE_ROOT):

{
  "command": "node",
  "args": ["/absolute/path/to/ContextEngine-plugin/dist/mcp-server.js"]
}

Environment (optional)

export CONTEXTENGINE_ROOT=/path/to/repo
export CONTEXTENGINE_AUTO_INDEX=1
# The MCP watcher is enabled by default; set to 0 to disable it
export CONTEXTENGINE_MCP_WATCH=1
# Optional: comma-separated alias:path roots
export CONTEXTENGINE_EXTRA_ROOTS=docs:/path/to/docs
export OPENAI_API_KEY=...

Tools exposed

ToolPurpose
codebase-retrievalAugment-compatible packed retrieval (call this first; codebase_retrieval is a legacy alias)
codebase_searchHybrid search → path, lines, symbol, content
get_task_contextPack ranked chunks under a token budget
get_file_contextRead a file / line range
index_statusIndex stats

Agent tip: call get_task_context first, then edit. Use codebase_search for follow-up queries.

The MCP server watches the workspace root and configured CONTEXTENGINE_EXTRA_ROOTS by default, then incrementally refreshes retrieval after debounced file changes. Set CONTEXTENGINE_MCP_WATCH=0 (also accepts false / off / no) to disable the watcher; with it disabled, CONTEXTENGINE_AUTO_INDEX=1 controls whether a missing index is built on the first MCP request.

HTTP service

The same retrieval core is available as an authenticated HTTP service for remote IDE clients and teams: source files are content-addressed Blobs in PostgreSQL; a client syncs only changed hashes, commits a workspace revision, and observes a background index job before querying.

Start

export CONTEXTENGINE_DATABASE_URL=postgresql://contextengine:contextengine@127.0.0.1:54329/contextengine
export CONTEXTENGINE_HTTP_API_KEY="$(openssl rand -base64 32)"

contextengine-http
# GET /health · GET /openapi.json
# Dashboard: http://127.0.0.1:8787/dashboard
# all /v1 routes use Authorization: Bearer <key>

Core endpoints: workspace create/list, /sync/plan, PUT /blobs/{sha256}, /sync/commit, /index-jobs (SSE progress), /search, /context, and /file. The complete client contract, payloads, and the packaged IntelliJ plugin mapping live in docs/HTTP_API.md.

Remote MCP (Streamable HTTP)

MCP-capable remote clients can use /v1/workspaces/{workspaceId}/mcp with the same Bearer key. The first request is initialize, which returns an mcp-session-id; subsequent requests expose the canonical codebase-retrieval tool for that workspace. Session metadata is persisted in PostgreSQL, so sessions can resume on any healthy instance and survive process restart without sticky routing. This JSON-response mode supports POST and idempotent DELETE; GET/SSE returns 405 because live streams are not reconstructable.

Observability dashboard

The HTTP server ships a self-contained /dashboard (same Bearer key as /v1/*) showing:

  • workspace revisions, indexed files, chunks, and embedding state;
  • recent indexing jobs and progress;
  • request volume, error rate, average and p95 latency by route;
  • process uptime and memory usage;
  • a live retrieval probe for indexed workspaces.

Request observations contain only method, normalized route, status, and latency; query text, source content, request bodies, and API keys are never captured. The dashboard polls same-origin GET /v1/observability/overview and needs no separate frontend build.

Docker Compose deployment

export CONTEXTENGINE_HTTP_API_KEY="$(openssl rand -base64 32)"
docker compose up -d --build
docker compose ps
# Dashboard published at http://127.0.0.1:8790/dashboard (loopback-only binding)

Set CONTEXTENGINE_DOCKER_HTTP_BIND_HOST=0.0.0.0 only for a trusted remote deployment. PostgreSQL and the HTTP runtime use named volumes, so a normal docker compose down preserves indexed data; use down -v only when the database really should be deleted.

Auth, ACLs, and connectors

  • Multi-principal auth — multiple Bearer keys (CONTEXTENGINE_HTTP_API_KEYS) or verified OAuth/OIDC JWTs (CONTEXTENGINE_OIDC_ISSUER) enforce reader / writer / owner permissions per workspace; OIDC principals stay stable across token rotation, and only server-configured group mappings can grant operator access;
  • Source policies — owners can apply default allow/deny plus nested path-prefix rules; the same policy is enforced by search, context, file reads, and Remote MCP;
  • Read-only connectors — GitHub, GitLab, Bitbucket Cloud, and static-website connectors attach external content to an empty Blob workspace and synchronize it incrementally; the website crawler enforces HTTPS/public-network, same-origin, path-prefix, robots, redirect, page-count, depth, and byte limits;
  • Webhooks and CI — signed GitHub / GitLab push webhooks idempotently trigger sync; source-scoped CI trigger tokens let a pipeline refresh one source without a workspace-wide API key (templates via contextengine ci-template).

Library API

Fully typed TypeScript, ideal for embedding retrieval in your own agent loop:

import { ContextEngine } from "contextengine-plugin";

const engine = ContextEngine.open({ root: "/repo" });

// index (with progress callback)
await engine.index((p) => console.log(p.phase, p.filesDone));

// stats
const stats = await engine.stats();

// search
const hits = await engine.search({ query: "…", topK: 8, mode: "auto" });

// pack context for a task
const packed = await engine.getTaskContext({
  task: "…",
  // optional caller-controlled transport cap: maxTokens: 16_000,
});

await engine.close();

Retrieval output is model-neutral: the engine retrieves, reranks, deduplicates, and formats the complete evidence selected by topK without inspecting model names or context-window sizes; pass maxTokens only when you explicitly need a smaller payload. Embedded hosts can also register additional source providers through connectorPlugins (contract in docs/PLUGINS.md).

Index snapshots

Active index generations can be shared as versioned, checksum-verified snapshots through filesystem or S3-compatible stores — new teammates don't have to re-index the whole repo.

contextengine snapshot export my-repo --store /shared/ce-snapshots
contextengine snapshot list        --store /shared/ce-snapshots
contextengine snapshot import my-repo --store s3://bucket/prefix
contextengine snapshot prune | gc  # clean old versions / garbage-collect

With CONTEXTENGINE_SNAPSHOT_STORE configured, the same operations (export, import, prune, GC) are exposed to owners through the HTTP service and return durable PostgreSQL job records with polling and SSE status; you can also persist interval-based or timezone-aware nightly replication schedules with throughput, lag, and bounded failure alerts. CLI snapshot commands remain synchronous. See docs/SNAPSHOTS.md.

Quality is not a slogan: the repo ships Recall / MRR / nDCG metrics, PR-level paired evaluation, and a multi-language benchmark — all reproducible locally.

contextengine eval --self --reindex

# Custom cases
contextengine eval --cases examples/eval.sample.json --root /path/to/repo

npm run bench:api

contextengine eval-pr \
  --manifest /path/to/pr-suite.json \
  --allow-exec \

Troubleshooting

Database error at startup

CONTEXTENGINE_DATABASE_URL (or DATABASE_URL) is required. Inside this repo, run npm run db:up to start the bundled pgvector service, then export postgresql://contextengine:contextengine@127.0.0.1:54329/contextengine. The pgvector extension is enabled automatically — no manual CREATE EXTENSION needed.

Node version error

Node.js ≥ 22.5 is required (declared in the engines field of package.json). Check with node -v and upgrade via nvm / fnm if needed.

Semantic search times out or slows down

  • Semantic / rerank stages each get a 2000ms per-query budget; on timeout the engine falls back to lexical results — nothing breaks, but ranking may differ, and the degraded channel is flagged in the trace;
  • After 3 consecutive failures the circuit breaker opens for 30 seconds and model calls are skipped;
  • Check that OPENAI_BASE_URL is reachable; both origin and /v1 forms are normalized.

Some files aren't indexed

  • Check the five-layer ignore rules (built-in filters → .gitignore → .augmentignore → .contextengineignore → --exclude);
  • Files over the size limit are skipped: 512 KiB by default, adjustable via CONTEXTENGINE_MAX_FILE_BYTES (hard max 32 MiB);
  • To index a path that .gitignore excludes, re-include it in .augmentignore with !path/.

MCP client gets no results

  • Confirm the MCP server's cwd or CONTEXTENGINE_ROOT points at the right workspace;
  • Set CONTEXTENGINE_AUTO_INDEX=1 so the first request builds a missing index, or run contextengine index manually first;
  • The MCP process needs CONTEXTENGINE_DATABASE_URL in its environment too.

HTTP requests return 401

All /v1 routes require Authorization: Bearer <key>, where the key is CONTEXTENGINE_HTTP_API_KEY (or one of the principals in CONTEXTENGINE_HTTP_API_KEYS). The dashboard uses the same key.

Old index missing after upgrading from 0.3.x

Since 0.4, index storage moved to PostgreSQL. Migrate a legacy local SQLite index once with contextengine migrate-sqlite <legacy-index.db> (CONTEXTENGINE_DATA_DIR only locates the old file).

FAQ

Does it work without embeddings?

Yes. BM25-only is a first-class mode: PostgreSQL FTS + symbols + paths + graph expansion + MMR packing all work, fully offline. Embeddings are an upgrade, not a prerequisite.

Which embedding services are supported?

Anything exposing an OpenAI-compatible /v1/embeddings endpoint: OpenAI itself, proxies, local gateways (e.g. Ollama-compatible layers), and self-hosted stacks. The production-validated self-hosted stack is Qwen/Qwen3-Embedding-0.6B plus the optional Qwen3-Reranker-0.6B — about 2.2 GB VRAM combined.

Does my code leave my machine?

Indexes and vectors live entirely in your own PostgreSQL. Only when you enable an external embeddings API is chunk text sent to the endpoint you configured (a self-hosted endpoint keeps everything in your network). The HTTP service's observability never captures query text or source content.

What's the relationship with Augment?

None — no affiliation. ContextEngine is an independent open-source component that aligns with the Augment Context Engine's system pattern and ecosystem compatibility (the codebase-retrieval tool name, .augmentignore semantics), and maintains an honest gap analysis — it does not claim parity.

How do I manage multiple repositories?

Three composable mechanisms: one PostgreSQL naturally isolates repos by absolute workspace path; contextengine profile switches the default workspace; CONTEXTENGINE_EXTRA_ROOTS merges a docs repo / extra directories into one index for joint retrieval.

Which programming languages are supported?

The multi-language chunker covers mainstream languages; the public benchmark ran 10 real OSS repos across TypeScript, JavaScript, Go, Python, C, C++, Java, Kotlin, and Rust (see Benchmarks). Lexical and symbol channels work for any text language.

How do I refresh the index from CI?

contextengine ci-template github|gitlab|bitbucket prints an installable workflow; HTTP deployments can use signed push webhooks, or issue a source-scoped CI trigger token that lets a pipeline refresh a single source without a workspace-wide API key.

How big is the index? How long does indexing take?

Indexing is incremental by file hash: after the first full pass, re-runs only process changed files, and watch / MCP mode refreshes automatically after a debounce. Index and query latency on mid-size OSS repos (hundreds to thousands of files) are reproducible yourself with npm run bench:suite.
