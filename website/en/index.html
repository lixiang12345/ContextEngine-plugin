Augment-class context

ContextEngine is a portable, open-source codebase context engine. It fuses keywords, symbols, paths, semantic vectors, the dependency graph, and commit history into one retrieval pass, then packs verifiable, line-anchored context under a token budget — so agents spend fewer tokens grepping and more turns shipping correct changes.

Why it exists

Agent tokens shouldn't be burned on blind grepping

Most coding agents explore large repos with repeated grep / find tool calls. Every round trip eats the context window — and still misses the right files.

Wasted turns

A single task can burn a dozen grep / file-read calls before any code gets written.

Context noise

Whole files dumped into the window dilute the model's attention with duplicate, irrelevant content.

Recall blind spots

Keyword match can't handle paraphrase; pure vectors miss exact symbols. Any single signal has blind spots.

The ContextEngine way

One call runs query understanding → parallel multi-signal recall → fusion & rerank → graph expansion → MMR packing, returning compact context with paths, line ranges, sources, and a retrieval trace. The agent calls codebase-retrieval first, then edits — instead of grepping ten times.

How it works

A six-stage pipeline of complementary signals

We clone the system pattern that makes proprietary retrieval models effective: understand → retrieve → fuse → rerank → expand → pack. When one channel is wrong, the others catch it.

Query understanding

Extract identifiers and path hints; classify intent (symbol / path / concept / history); expand terms.

Multi-signal recall

PostgreSQL FTS (tsvector+GIN), symbol table, path match, and pgvector KNN run in parallel.

RRF fusion

Reciprocal Rank Fusion merges channel rankings — robust when any single channel is wrong.

Code-aware rerank

Feature scoring over symbols, paths, identifier overlap, and language; optional neural /v1/rerank stage.

Graph expansion

Walk the import / symbol graph to pull in files related to the candidates.

MMR packing

Diversity dedup by path, then emit line-anchored evidence chunks under the token budget.

The semantic channel is optional: without embeddings the engine runs fully offline in BM25-only mode — still useful. Every response carries a reproducible trace (intent, channels, degradations, token usage).

Features

A small but complete retrieval layer

Not another vector-database demo — a full component covering indexing, retrieval, packing, observability, and team workflows.

Lexical search that scales

PostgreSQL tsvector + GIN indexes with database-side filtering — no full-content maps in process memory.

Exact symbol search

A declaration-level symbol table with exact and prefix matching — "find processPayment" no longer depends on vector luck.

Semantic search (optional)

Any OpenAI-compatible embeddings endpoint plugs in; pgvector cosine KNN + HNSW, with a two-stage pass over candidates only.

Fusion + code-aware rerank

RRF across channels, then feature scoring over symbol / path / identifier overlap / language; optional neural second stage.

MMR context packing

Diversity dedup by path under a token budget, with raw / extractive packing policies.

Symbol / import graph

After recall, expansion along the dependency graph brings in the "you'll also need to look at" files.

Multi-root workspaces

Code repo + docs repo + extra directories in one index (CONTEXTENGINE_EXTRA_ROOTS) — one query covers all.

Commit lineage

Recent git history is indexed as searchable chunks — "why did this change recently" is retrievable too.

Watch-mode incremental index

Hash-based incremental indexing with debounce; MCP mode watches the workspace by default, so the next query reflects your edits.

Reproducible retrieval trace

Every response carries intent, contributing / degraded channels, candidate→packed counts, token budget, and index generation.

Augment-compatible ignore rules

Built-in smart filters + .gitignore + .augmentignore (with ! re-include) + .contextengineignore.

Team index snapshots

Versioned, checksum-verified filesystem / S3-compatible snapshots with export, import, replication, and schedules.

Ops dashboard

The HTTP server ships a self-contained /dashboard: workspace state, index jobs, p95 latency, error rate, and a live retrieval probe.

Integration

Four form factors, one retrieval core

MCP plugin, CLI, authenticated HTTP service, TypeScript library — pick whatever fits your agent architecture; retrieval quality is identical.

LIBRARY · TYPESCRIPT

A fully-typed library API — indexing, search, packing, and stats are all programmable.

const engine = ContextEngine.open({ root: "/repo" });
await engine.index();
const hits = await engine.search({ query: "auth middleware" });
const packed = await engine.getTaskContext({ task: "…" });

Honest comparison

vs Augment Context Engine

We are an open, portable building block, not a full commercial context platform. The trade-offs, stated plainly:

CapabilityContextEngineAugment
Open source / self-host / offline ✓ MIT; BM25-only works fully offline ✗ commercial product
MCP + hybrid search ✓ stdio + Remote MCP, multi-signal fusion ✓ local + hosted MCP
Custom-trained code retrieval models ✗ BYO OpenAI-compatible embeddings ✓ paired, purpose-trained models
Multi-source content (git hosts / websites) ◐ connector SDK + GitHub / GitLab / Bitbucket / static sites ✓ packaged enterprise connector matrix
Huge-monorepo scale ◐ PostgreSQL architecture, validated on mid-size repos ✓ production monorepo indexing
Cost & ownership ✓ own your infra; pay only for embedding API usage ◐ product pricing (free query tier)

Design principle #5 is "honest scope": we optimize for ownership and hackability and do not claim Augment parity. The line-by-line gap analysis lives in COMPARISON.md and the alignment audit.

Quick start

Your first retrieval in three steps

All you need is Node.js ≥ 22.5 and a PostgreSQL with pgvector (a local Docker Compose is included).

Prepare the database

Use the bundled local pgvector service, or point at any existing PostgreSQL.

git clone https://github.com/lixiang12345/ContextEngine-plugin.git
cd ContextEngine-plugin && npm install && npm run build
npm run db:up
export CONTEXTENGINE_DATABASE_URL=postgresql://contextengine:contextengine@127.0.0.1:54329/contextengine

Index a workspace

Indexes live in PostgreSQL, namespaced by the workspace's absolute path — one database safely holds many repos.

npx contextengine-plugin index /path/to/your/repo

Search, or pack context for a task

Runs in BM25-only mode without an API key; set OPENAI_API_KEY to upgrade to hybrid semantic search.

npx contextengine-plugin search "stripe payment webhook"
npx contextengine-plugin context "Add logging to payment requests"
